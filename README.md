# H题第二问：车载巡线一圈控制系统

本工程面向立创·天猛星 MSPM0G3507、拓展板 TB6612FNG、MG513XP28_12V
霍尔编码器电机、8路红外巡线模块和 0.96 英寸 SSD1306 OLED。

第二问完全不使用 ICM-45686。循迹由8路红外完成，左右轮速度和接近终点的
里程估算由编码器完成。

## 上电前必须处理

### 1. 编码器5V电平风险

拓展板把两个编码器 VCC 接到5V，而 A/B 信号直接进入 PB4、PB5、PB11、
PB12，中间没有电平转换。这些 PB 引脚不是5V容忍引脚。

MG513X霍尔编码器资料允许3.3～5V供电，推荐把两个编码器 VCC 改接3.3V并
保持共地。完成后把
[`src/vehicle_config.h`](src/vehicle_config.h) 中：

```c
#define CFG_ENCODER_INPUT_LEVEL_SAFE (0)
```

改成：

```c
#define CFG_ENCODER_INPUT_LEVEL_SAFE (1)
```

默认值为0时，程序等待巡线模块稳定20秒后会显示 `ENC 5V UNSAFE`，并拒绝
启动电机。这是有意设置的安全锁。

内部上拉不是电平转换。如果继续5V供电，不能靠开启上拉解决过压问题。

### 2. 检查8路巡线输出高电平

巡线模块由5V供电。接入单片机前建议用万用表或示波器测量 X1～X8 的高电平，
确认不超过单片机3.3V逻辑允许范围。当前8路输入均启用了内部上拉，黑线按
低电平有效处理。

### 3. 避免电机堵转

MG513X堵转电流约3.2A，明显高于 TB6612 单通道持续电流能力。程序最大占空比
限制为90%，但机械堵转仍可能使驱动板过热。首次测试必须架空车轮，并避免长时间
卡住车轮。

## 编码器和里程

编码器为13PPR，减速比1:28。只对A相开中断，但同时统计上升沿和下降沿：

```text
13 × 28 × 2 = 728 计数/车轮圈
```

轮胎外径按已确认的65mm：

```text
轮周 = π × 65 ≈ 204.20 mm
```

程序使用左右轮绝对增量的平均值估算车辆中心行驶距离：

```text
distance =
    (|right_count| + |left_count|) / 2 × π × 65 / 728
```

理论赛道中心线约6142mm，对应平均编码器计数约21900。当前设置：

- 0～5400mm：目标165rpm；
- 5400mm以后：降到82rpm；
- 5700mm以后才允许识别终点横线；
- 同时要求运行至少7秒，且已经离开起点横线；
- 至少4路连续20ms检测到黑线时短制动；
- TB6612短制动120ms后转为滑行状态，避免长期发热；
- 25秒仍未找到终点则保护停车。

理论正常直线速度约0.56m/s，包含末段降速后预计一圈仍明显小于20秒。实际时间
由地面摩擦、转弯和PID参数决定。

## 控制流程

1. 上电后电机保持停止，等待20秒让8路巡线探头稳定。
2. OLED显示 `READY` 后按 Q1。
3. 先屏蔽起点横线；连续100ms检测到普通窄线后，才允许以后识别终点。
4. 每5ms读取8路传感器，按 X1～X8 的加权质心计算偏差。
5. 巡线使用位置PD，输出为左右轮目标转速差。
6. 每10ms用双编码器独立PI控制左右轮转速。
7. 里程达到5400mm后降速。
8. 里程超过5700mm并检测到终点横线后，短制动停车。
9. OLED保留本圈总时间；再次按 Q1 回到 `READY`，下一次启动会重新锁存编码器
   基准，不累计上一次的里程。

## OLED界面

- `WARMUP`：巡线模块稳定倒计时。
- `READY`：允许按键启动。
- `RUN`：正在巡线。
- `BRAKE`：终点短制动。
- `STOP`：已停车并保持本次总时间。
- `R / L`：右、左实测车轮rpm，架空测试时用于判断编码器方向。
- `Dxxxx`：本圈估算里程，单位mm。
- `Lxx`：8路黑线位图，X1对应bit0，X8对应bit7。
- `Nn`：当前检测到黑线的探头数量。
- `LINE LOST`：连续350ms没有检测到线，保护停车。
- `TIMEOUT`：运行25秒仍未完成，保护停车。

## 首次架空调试

1. 断开12V电机电源，先完成编码器3.3V改线和逻辑电平测量。
2. 把 `CFG_ENCODER_INPUT_LEVEL_SAFE` 改为1。
3. 为降低首次方向测试风险，可临时修改：

   ```c
   #define CFG_SPEED_NORMAL_RPM (30.0f)
   #define CFG_SPEED_MAX_RPM    (50.0f)
   ```

4. 在 CCS 中导入整个 `H2_LineCar_CCS` 文件夹，执行 Clean Project 和 Build
   Project。
5. 确认烧录器类型后烧录，架空两个驱动轮，上电等待20秒，再按 Q1。
6. 从车辆后方向前看，两个轮子都应使车辆向前：

   - 右轮反转：翻转 `CFG_RIGHT_FORWARD_IN1_HIGH`；
   - 左轮反转：翻转 `CFG_LEFT_FORWARD_IN1_HIGH`。

7. 物理前进方向正确后观察 OLED 的 R/L：

   - 右侧rpm为负：翻转 `CFG_RIGHT_FORWARD_WHEN_A_EQUALS_B`；
   - 左侧rpm为负：翻转 `CFG_LEFT_FORWARD_WHEN_A_EQUALS_B`。

8. 手持黑线依次经过探头：

   - X1黑线时应显示 `L01`；
   - X8黑线时应显示 `L80`；
   - 横向宽黑线应显示 `N4`～`N8`。

9. 方向全部正确后恢复165rpm和220rpm上限，再进行地面低速测试。

## 实车调参顺序

1. 先只确认左右轮方向和编码器正负，不调巡线PID。
2. 在直线测试左右轮速度，修改 `CFG_SPEED_KP`、`CFG_SPEED_KI`。
3. 低速循迹：

   - 左右振荡明显：减小 `CFG_LINE_KP_RPM`；
   - 转弯反应迟钝：增大 `CFG_LINE_KP_RPM`；
   - 入弯冲过后才纠正：适当增大 `CFG_LINE_KD_RPM`。

4. 标定有效轮径：让车辆实际行驶1000mm，读取OLED估算里程 `D`，使用：

   ```text
   新轮径 = 65 × 1000 / OLED显示里程
   ```

5. 最后再调终点：

   - 接近终点仍太快：降低 `CFG_SPEED_FINISH_RPM`；
   - 太早减速：增大 `CFG_FINISH_SLOWDOWN_DISTANCE_MM`；
   - 冲过终点：先降低末段转速，再小幅增加 `CFG_ACTIVE_BRAKE_MS`；
   - 误把宽线当终点：增大 `CFG_FINISH_ARM_DISTANCE_MM` 或把宽线阈值改为5路。

所有可调参数都集中在
[`src/vehicle_config.h`](src/vehicle_config.h)，无需修改生成文件。

## 工程文件边界

- `empty.syscfg`：引脚、PWM、I2C、定时器和中断的配置源。
- `main.c`、`src/*.c`、`src/*.h`：应用源码，可以修改。
- `syscfg/*`：本次交付附带的生成结果，仅供检查宏名；以后应由 SysConfig
  重新生成，不要手工编辑。
- `targetConfigs/*`：CCS目标配置，烧录前确认调试器。

巡线error
error = 0：黑线在正中间。
error < 0：黑线位于传感器左侧。
error > 0：黑线位于传感器右侧。
|error| 越大：偏离中心越严重。

巡线KP：
左右快速摆动、车身抖动：KP 仍然偏大。
碰到线但转不过来：KP 偏小。
能平滑跟线：KP 合适

CFG_SPEED_STEER_LIMIT_RPM：
#define CFG_SPEED_STEER_LIMIT_RPM          (70.0f)//
这个宏的意思是：
作用：设置“转向/修正时允许的速度上限”，单位是转/分（RPM）。
也就是当车辆进行巡线纠偏、转向修正或者偏离中心线时，系统会限制车轮速度不超过这个值，避免纠偏过猛、打滑或失控。
在你这个项目里，它通常是一个“速度环的限制阈值”：
例如如果当前速度接近或超过 70 RPM，控制器就不会继续让它再往上加速或继续强烈修正。
目的是让车在弯道/纠偏时更稳，尤其是低速阶段
70.0f = 这个“转向限制速度”是 70 RPM
不是“绝对最大速度”，而更像“纠偏/转向时的安全上限”

巡线 PD 和速度 PI 的区别：
| 控制环   | 输入               | 输出       | 负责什么         |
| ----- | ---------------- | -------- | ------------ |
| 巡线 PD | 黑线位置误差 `error`   | 左右轮目标转速差 | 控制方向         |
| 速度 PI | 目标 rpm－编码器实际 rpm | PWM 占空比  | 控制每个车轮达到目标速度 |
